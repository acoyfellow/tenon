# The overlap

coil, hark, my-ax, chat-ax and skin look different: a cloud computer, a voice agent, a personal assistant, a team chat, and an app that rewrites itself. Under the surface they all build the same nine things. tenon names those nine things, implements each one in one small Worker, and `basic/kernel` checks any app against them.

These are the invariants. Each one is falsifiable. The machine-readable source is [`invariants.json`](invariants.json).

| ID | Invariant | Breaks if |
|---|---|---|
| T1 | Every non-public request has a verified owner (Access JWT or a signed Sign in with Cloudflare session). | A forged, tampered, or missing identity reaches app state. |
| T2 | State lives in a Durable Object keyed by that owner. The owner key comes from identity, never from the request. | One owner reads another owner's state, or a header or query picks the owner. |
| T3 | The payer is explicit. A user-paid turn never falls back to host inference. | A signed-in user's call is billed to the host without the operator choosing it. |
| T4 | Secrets and grant tokens never reach the browser, a response body, or a log. | A token appears in any response or log line. |
| T5 | Writes come from the app's own origin. | A signed-in cookie lets another site write. |
| T6 | Code the agent writes runs in an isolate with no ambient network and no secrets. | Agent code reaches the network or a binding it was not given. |
| T7 | A run is visible while it runs, ends with a truthful status, and a stop sticks. | A run shows "running" forever after eviction, or a late result overwrites a stop. |
| T8 | Changes the agent makes are versioned, gated, and append-only. | A failing change goes live, or rollback rewrites history. |
| T9 | Public pages (landing, docs, `/llms.txt`, `/robots.txt`) are served before the gate. Nothing else is. | An API route answers without identity, or a public page needs sign-in. |

## Gaps, per app

**coil (7/9).**
- **T3:** it routes to the user account, but `src/thread.ts:674` calls `this.env.AI.run` for vision. Confirm that a `cf:` owner never takes that path, or route it to the user account.
- **T9:** it has a public path list, but no single `PUBLIC` set that the gate reads.

**hark (8/9).**
- **T8:** the agent's memories and workbench changes have no version history and no rollback. An earlier probe matched the OAuth scope string `artifacts.read`; that was noise and is fixed. hark is the app most likely to need T8 next, because it remembers you.

**my-ax (7/9, plus 1 n/a).**
- **T3:** it uses host AI on purpose (Access-gated, operator pays), but nothing in code states the payer. Add an explicit payer setting.
- **T9:** there is no public `/llms.txt` or `/robots.txt` before Access. This is correct for an Access-only app, so it is recorded as n/a in `basic/kernel/optouts.json`.

**chat-ax (4/9).** This app has the most gaps.
- **T5:** no Origin check on writes. Cookies alone carry auth.
- **T6:** no isolate for agent code. It has connectors, not code execution. If it ever runs agent code, this becomes critical.
- **T8:** no versioned agent changes.
- **T9:** no public pages.
- **T3:** host AI with no stated payer.

**skin (8/9).**
- **T5:** it relies on cookie `SameSite`. No server-side Origin check on writes. Add one. A single line closes it.
- Note: skin is the reference for T8 (gated generations in DO SQLite). tenon's T8 is a smaller copy of it.

## What tenon is

tenon is one Worker (`src/index.ts`, about 350 lines) that implements T1–T9 and nothing else:

- **Identity (T1):** Access JWT verification, or an HMAC-signed session.
- **Owner state (T2):** one `Owner` Durable Object per owner, with SQLite.
- **Payer (T3):** `TENON_PAYER` is `user`, `host`, or `none`. A user payer with no grant fails with `no_user_grant` and does not fall back.
- **Secrets (T4):** the grant token is stored in the DO and never returned.
- **Origin (T5):** writes are refused unless `Origin` matches the app.
- **Isolates (T6):** versions and runs execute in Worker Loader isolates with `globalOutbound: null`.
- **Runs (T7):** runs are `running` → `done` | `failed` | `stopped` | `interrupted`. A stop is never overwritten.
- **Versions (T8):** a version goes live only if it loads and answers `GET /` with 200. Rejected versions stay in history. Rollback appends a new version.
- **Public pages (T9):** only `/`, `/llms.txt` and `/robots.txt` are public.

It is not a product. It is the smallest code that passes the checks, so each app can compare itself against something that does.

## Proof

`bash tenon/gate.sh` runs:
1. the typecheck
2. 15 security checks against a real local workerd (`test/security.mjs`, no mocks)
3. the kernel layer on tenon in strict mode (9/9)
4. kernel reports for all five apps, with file:line evidence
5. a check that this file names every invariant and app
6. the demo, which writes `receipts/demo.png` and `receipts/demo.json`

## Not done

- **Kernel checks are mostly static.** The live probes run only when `BASE` is set. The deployed apps sit behind Access or OAuth, so a live run needs a service token or session cookie per app.
- **No Sign in with Cloudflare flow yet.** tenon has no OAuth flow. The local session login (`/dev/login`) is for local tests only and is off unless `TENON_DEV_LOGIN=1`.
- **Not deployed.** Deploy behind Access only.
